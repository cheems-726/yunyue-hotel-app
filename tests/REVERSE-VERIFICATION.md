# 防回归断言 · 逆向验证记录（2026-09-20）

## 为什么需要这份记录

2026-09-19 引入的布局回归（切页动画包装层缺 flex 约束 → `.tabbar` 被顶出视口 2200px、
`.content` 零滚动区间）**潜伏到 9-20 真机才暴露**，原因是当时的断言：

1. 全用 JS `element.click()` —— 程序化点击**不做可操作性检查**，元素在视口外也能点
2. 只读 `innerText`（文本存在性），**零布局几何断言**
3. 无性能断言
4. 测试视口 480×900 而内容恒 2500px+，**从第 1 周就是坏的**，但没有断言会因此失败

新增的 `assertLayout()`（`tests/ui-smoke.mjs:64`）就是这次的防线。本记录证明它**真的能抓住这个 bug**。

## 新增断言（共 27 条，冒烟 47 → 74）

调用点 7 处：学生 4 个 tab（经营页/报表/口碑/我的）+ 教师 3 个视图（实时决策/排名/我的）。

每个页面断言：

| 断言 | 内容 | 能否抓住本次 bug |
|---|---|---|
| `.tabbar` 在视口内 | `rect.bottom ≤ innerHeight+1` 且 `rect.top > 0` | ✅ **能**（坏状态下 top=2522 / bottom=2613，视口 900） |
| `.tabbar` `checkVisibility()` | 元素未被 display/visibility/opacity 隐藏 | ❌ **不能**——它不反映被 overflow 裁切，坏状态下仍返回 `true`（见下方日志，7 个失败页面里该项全部为 ✓） |
| 滚到底内容可达 | `scrollTop = scrollHeight` 后，`.content` 末元素底边进入视口 | ✅ **能**（坏状态下 `scrollTop` 动不了=0，末元素底=2489） |
| 溢出时可实际滚动 | `scrollHeight > clientHeight` 时，赋值 `scrollTop` 后确实变化 | ✅ 能（坏状态下 `scrollHeight === clientHeight`，此条直接不触发，由"滚到底可达"兜住） |

> 结论：**checkVisibility() 单独用是不够的**——本次 bug 正是"元素存在、未被隐藏、只是被父容器裁到视口外"。承载判定的是 rect 断言与"滚到底可达"断言。这也解释了为什么旧的"存在性 + element.click()"断言会全绿。

## 结论

- 新断言**能稳定抓住**该类布局回归：撤销修复 → 必然 7 条失败（两次重复一致）；还原 → 必然全绿
- 失败时冒烟**退出码为 1**，可直接用于 CI / 提交前门禁
- 旧断言对这类 bug 完全失明（47 条在坏状态下照样全过）——`element.click()` + `innerText` 的存在性断言不能替代几何断言
- `.tabbar` 在视口内 = 由 rect 判定，**不能只靠 `checkVisibility()`**
